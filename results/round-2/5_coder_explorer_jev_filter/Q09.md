- Validate all input: Ensure that every piece of data received by the program from external sources is checked for correctness, type, length, format, and range before it is used, to prevent malformed or malicious data from causing harm. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md) [JEV 0.91]
- Keep it simple: Design and write code as simply as possible. Complexity increases the attack surface and the likelihood of introducing vulnerabilities. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md) [JEV 0.83]
- Default deny: Use a 'deny by default' approach so that access to resources, features, or data is denied unless explicitly permitted, reducing exposure to unauthorized actions. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices for Software Development.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Software Construction Security and Privilege Management.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.96]
- Sanitize data sent to other software: Clean and validate all data before passing it to other systems, components, libraries, or databases to prevent injection attacks and other inter-component exploits. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices for Software Development.md) [JEV 0.88]
- Practice defense in depth: Layer multiple security controls and mechanisms so that if one control fails, others remain to protect the system. (source: root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md) [JEV 0.89]
- Use effective quality assurance techniques: Apply quality assurance methods such as unit testing, integration testing, test-first development, use of assertions, defensive programming, debugging, inspections, security-oriented technical reviews, and automated static code analysis to detect and eliminate security weaknesses in code. - Adopt a software construction security standard: Follow an established, recognized coding security standard throughout the construction phase to ensure consistent application of secure coding rules. (source: root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md) [JEV 0.92]
- Validate program assumptions and document those that cannot be validated: Ensure that all assumptions the program makes are explicitly validated in code. Where validation is not possible, document the assumptions so that installers and maintainers are aware of them — because those are the assumptions attackers will try to invalidate. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.97]
- Ensure [SWEBOK excerpt 08ff146473463cf47916] other programs: Avoid shared memory between programs to prevent one program from reading or corrupting another's data, which attackers could exploit. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.95]
- Check every function's error status and handle errors securely: Examine the return/error status of every function call. If recovery is not possible without security implications, restore the software to its previous state and terminate rather than continuing in an insecure state. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.97]
- Choose programming languages carefully with security in mind: The choice of programming language significantly affects [SWEBOK excerpt c7d8f7433446a905b947]. When using cryptography, carefully select cryptographic algorithms and manage cryptographic material (keys) through their full lifecycle of creation, distribution, and management. (source: root/Software Construction Techniques and Practices/Construction Quality Techniques and Practices.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Cryptographic Controls and Secure Software Construction.md) [JEV 0.94]
