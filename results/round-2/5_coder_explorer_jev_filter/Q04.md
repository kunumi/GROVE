# Guidelines
- Use fault tolerance techniques — backing up and retrying, using auxiliary code with voting algorithms, and replacing erroneous values with phony (benign) values — to detect errors and recover from them or contain their effects when recovery is not possible. (source: root/Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md) [JEV 0.96]
- Apply exception handling (try-catch blocks with throw) [SWEBOK excerpt faa5a8a24fd72e5b9ae1] at runtime. Design exception-handling policies carefully: include all information that led to the exception in the exception message, avoid empty catch blocks, know what exceptions library code throws, consider building a centralized exception reporter, and standardize the program's use of exceptions. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
- Use a range of error-handling techniques to keep the system running rather than failing: [SWEBOK excerpt 4922a3a9427679f66da0] — as a last resort — shutting down the software gracefully. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.91]
- Apply defensive programming to protect routines from invalid inputs: check the values of all input parameters and decide how to handle bad inputs before they can propagate and cause failures. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md) [JEV 0.97]
- Use assertions — executable predicates placed in a program that perform runtime checks — especially in high-reliability programs, to surface mismatched interface assumptions and errors introduced during code modification before they cause failures. (source: root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md; root/Software Construction Techniques and Practices/Parameterization, Templates, Generics, and Assertions.md) [JEV 0.97]
- Apply Design by Contract — specifying preconditions and postconditions for each routine — so that each routine or class forms an explicit contract with the rest of the program, making violations detectable and improving robustness. (source: root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md; root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md) [JEV 0.96]
- Treat errors and exception handling as a design-level architectural concern (alongside distribution, data persistence, and event handling) so that the entire system strategy for preventing, avoiding, mitigating, tolerating, and processing errors is planned at architecture time. (source: root/Software Design Concerns, Documentation, and Modeling/Software Design Concerns and Architectural Patterns.md) [JEV 0.72]
- During construction, embed quality techniques such as the use of assertions, defensive programming, debugging, inspections, and technical reviews to catch faults early — including security vulnerabilities — before they manifest as runtime failures. (source: root/Software Construction Techniques and Practices/Construction Quality Techniques and Practices.md) [JEV 0.96]
