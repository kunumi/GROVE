# Guidelines
- Use equivalence partitioning to divide the input domain into subsets (equivalence classes) — valid ranges and invalid/out-of-range ranges — and select at least one representative test case from each class. This ensures the function is tested for inputs it should accept and inputs it should reject or handle as errors. (source: root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md; root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.96]
- Apply boundary value analysis by choosing test inputs on or near the boundaries of the valid input range (e.g., the minimum valid value, maximum valid value, and values just inside those limits), because [SWEBOK excerpt 44266d1663bca03e93fd]. (source: root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.97]
- Extend boundary value analysis with robustness testing by also choosing test inputs outside the valid input domain (e.g., values just below the minimum and just above the maximum) to verify how the function handles unexpected or erroneous inputs. (source: root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.96]
- Include test cases that force exception conditions — such as overflow, underflow, or data exceptions — to verify that the function correctly manages these predefined error scenarios. Focus especially on negative test scenarios that cause the generation of error messages. (source: root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Exception Testing and Error Handling in Software Testing.md) [JEV 0.97]
- Supplement deterministic test case selection (e.g., equivalence partitioning, boundary value analysis) with randomly drawn inputs from the input domain distribution to increase coverage, particularly for reliability testing. The input domain must be known in order to pick random points within it. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Deterministic vs. Random Test Case Selection.md; root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Random Testing and Evidence-Based Software Engineering Approaches.md) [JEV 0.79]
- Use combinatorial test techniques (such as All-Combinations, Pair-Wise, Each-Choice, or Base-Choice testing) to systematically derive test cases that cover specific parameters, values, or conditions when the function has multiple input parameters that interact. (source: root/Software Testing Methodologies and Techniques/Combinatorial Test Techniques Overview.md) [JEV 0.94]
