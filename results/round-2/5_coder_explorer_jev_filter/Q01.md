# Guidelines
- Represent the component under test as a finite-state machine (FSM): identify all states, the events (inputs) that trigger transitions, and the resulting output or actions. State Transition Testing techniques are grounded in this FSM model of the system under test. (source: root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md) [JEV 0.87]
- Derive positive test cases by exercising every defined state transition: for each (current-state, event) pair that is explicitly specified in the model, create a test case that verifies the component moves to the correct next state and produces the correct output. (source: root/Requirements Management, Quality, and Testing Practices/Deriving Test Cases from Requirements Models.md) [JEV 0.93]
- Derive negative test cases from state-and-event combinations that are NOT defined in the model: apply events in states where they are not expected and verify the component handles them correctly (e.g., ignores them or raises an error). (source: root/Requirements Management, Quality, and Testing Practices/Deriving Test Cases from Requirements Models.md) [JEV 0.96]
- Use UML state models (or equivalent behavioral specification models) as the basis for systematic test-case derivation; a formal [SWEBOK excerpt ab7d0220987d936feb3a] supports complete and traceable coverage of the component's behavior. (source: root/Requirements Management, Quality, and Testing Practices/Deriving Test Cases from Requirements Models.md) [JEV 0.89]
- Apply model-based testing (a specification-based, black-box technique) so that test cases reflect the behavioral specification of the component—its states, transitions, and events—rather than its internal implementation details. (source: root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md) [JEV 0.81]
- When using tools to generate test cases from state models, be aware that such tools can typically generate only test-case inputs automatically; determining the expected result for each transition may require additional business-domain expertise and manual effort. (source: root/Requirements Management, Quality, and Testing Practices/Deriving Test Cases from Requirements Models.md) [JEV 0.97]
- Complement state-transition test cases with scenario-based testing: construct workflows or sequences of events (scenarios) that exercise chains of transitions, ensuring that typical paths and alternate paths through the state machine are both covered. (source: root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Scenario-Based Testing Components and Workflow Models.md; root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Scenario-Based and Random Testing Approaches.md) [JEV 0.91]
