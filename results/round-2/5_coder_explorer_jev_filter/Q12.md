- Separate interface from implementation: define each component by its public interfaces accessible to clients and isolate usage of the component from the details of how it is built. (source: root/Foundations of Software Architecture/Software Architecture Foundations and Design Principles/Software Design Principles and Processes/Modular Design and Core Software Principles/Software Design Principles and Module Organization.md) [JEV 0.98]

- Use top-down decomposition (structured design): identify major software functions and elaborate them in a top-down manner, producing a hierarchy of modules where each level refines the one above. - Record design rationale — including prior assumptions, alternatives considered, and trade-offs analyzed — because reasons obvious to the current team can be opaque to future maintainers. - Improve a badly structured program through refactoring: reorganize the program without changing its observable behavior.
