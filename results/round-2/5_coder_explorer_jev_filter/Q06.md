# Guidelines
- Use combinatorial test techniques to systematically derive test cases covering specific parameters and their values, rather than testing every possible combination. The standard combinatorial [SWEBOK excerpt d29e0634857acb6fd217]. (source: root/Software Testing Methodologies and Techniques/Combinatorial Test Techniques Overview.md) [JEV 0.92]
- Apply Pair-Wise (t-wise) Testing: derive test cases by combining the values of every pair (or every t-tuple) of input parameters. This is also known as Orthogonal Array Testing (OAT). It dramatically reduces the number of test cases compared to all-combinations testing while still covering all two-way (or t-way) interactions. (source: root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing and Decision Tables.md) [JEV 0.95]
- Apply Equivalence Partitioning first: partition the input domain of each parameter into equivalence classes (valid and invalid inputs) and select a representative test case from each class, rather than testing every individual value. (source: root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md; root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.96]
- Apply Boundary Value Analysis: choose test cases on or near the boundaries of each parameter's input domain, since [SWEBOK excerpt 44266d1663bca03e93fd]. For robustness, also include test cases outside the input domain to test handling of erroneous inputs. (source: root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.97]
- Use Decision Tables to represent logical relationships between parameter conditions (inputs) and resulting actions (outputs), then systematically derive test cases covering every combination of conditions and their actions. This technique is especially useful for documenting [SWEBOK excerpt 53592579e03cd896984d]. (source: root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing and Decision Tables.md; root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing for Knowledge Representation and Documentation.md) [JEV 0.92]
- Use Cause-Effect Graphing: build logical networks that map each input condition (cause) to its output (effect) [SWEBOK excerpt dcd2e342d000b7c78bad], identifying relevant causes and consequent output conditions. (source: root/Software Testing Methodologies and Techniques/Cause-Effect Graphing Techniques.md; root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md) [JEV 0.95]
- Consider combining specification-based (black-box) techniques — such as equivalence partitioning and combinatorial methods — with structure-based (white-box) techniques, as these two approaches are complements that use different information sources and highlight different problems. They can be combined based on organizational and budgetary constraints. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Combining Functional and Structural Testing Techniques.md) [JEV 0.95]
- Consider supplementing systematic combinatorial test cases with randomly selected test cases drawn from some distribution of inputs, since random selection can complement deterministic techniques and may be more effective under certain conditions. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Deterministic vs. Random Test Case Selection.md) [JEV 0.77]
