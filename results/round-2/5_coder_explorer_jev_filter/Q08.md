# Guidelines
- Define regression testing as selective retesting: after any modification, run a carefully selected subset of the existing test suite to verify that changes [SWEBOK excerpt 9719b1133051fb8e8d26] system still complies with its specified requirements. (source: root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md) [JEV 0.96]
- Decide what to re-test by combining test-case selection, minimization, and prioritization: select the most relevant tests from the existing suite, reduce redundancy (minimization), and schedule the remaining cases to maximize fault-detection rate and code coverage early in the run. (source: root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md; root/Software Testing Levels, Objectives, and Approaches/Test Case Prioritization for Fault Detection.md) [JEV 0.95]
- Prioritize test cases using similarity-based or other heuristic strategies [SWEBOK excerpt c5ce46e06ec01d7341a5], improve code coverage, and strengthen system reliability within the available time and budget. (source: root/Software Testing Levels, Objectives, and Approaches/Test Case Prioritization for Fault Detection.md) [JEV 0.95]
- Cover both functional and non-functional dimensions when re-testing: regression testing may encompass [SWEBOK excerpt 6081dd06be3ad080f185]—not just functional correctness. (source: root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md) [JEV 0.97]
- Apply regression testing at every test level (unit, integration, system, acceptance) where the change could have propagated; do not restrict re-testing to a single stage. (source: root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md; root/Software Testing Levels, Objectives, and Approaches/Software Testing Levels and Stages.md) [JEV 0.91]
- In shift-left and Agile processes, treat internal code quality—covering regression, security, and privacy—as a primary objective; run unit and integration tests (using structure-based techniques) first after every change. (source: root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Aspects in Shift-Left Development.md) [JEV 0.90]
- In Agile development, manage regression risk explicitly as part of the testing process: account for changing requirements and their impact on test artifacts in every iteration. (source: root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Strategies Across Methodologies and Domains/Testing Techniques Across Development Levels and Shift-Left Approaches.md) [JEV 0.96]
- In DevOps / continuous-integration pipelines, run regression testing continuously after every build so that development and integration issues are identified and corrected promptly; use smoke testing (Build Verification Testing) first to confirm the build is testable before the full regression suite is released to the operational stage. (source: root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Strategies Across Methodologies and Domains/Test Automation and Domain-Specific Testing Approaches.md; root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Smoke Testing and Knowledge-Based Testing Approaches.md) [JEV 0.97]
- Use test automation to manage regression risk, reserving exploratory testing to handle areas where detailed requirements are lacking. (source: root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Strategies Across Methodologies and Domains/Test Automation and Domain-Specific Testing Approaches.md) [JEV 0.96]
- Promote the shift-left principle: adopt testing as early as possible in the development process to detect and remove faults sooner, increasing overall quality and reducing the cost and risk of later testing activities. (source: root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Unified Process Phases and Shift-Left Testing Movement.md) [JEV 0.98]
- Perform regression testing [SWEBOK excerpt 0f6027292d0f7e6a203b]: this is the standard placement of regression in the testing workflow. (source: root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md) [JEV 0.97]
- Balance the assurance provided by regression testing against the resources it consumes: when it is impractical to run every test after every change, apply trade-off analysis and use test-case selection and minimization to keep the suite manageable. (source: root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md) [JEV 0.84]
- Combine functional (scenario-based) and structural (code-based) test-case selection when deciding what to re-test: the two approaches are complementary, exploit different information sources, and reveal different categories of problems. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Combining Functional and Structural Testing Techniques.md) [JEV 0.96]
- Invest in test-case reusability: reusable test cases reduce the cost and effort of regression testing and improve its effectiveness across releases and product variants. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Test Planning and Reusability Strategy/Test Case Reusability in Software Development.md) [JEV 0.96]
