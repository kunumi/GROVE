### Guidelines for Measuring Numerical Discrepancy in Tests

**1. Distinguish between accuracy and precision before choosing a comparison method.**
Accuracy is the closeness of a computed value to the true value, while [SWEBOK excerpt becdd22b8760d88fed4e]. The two are distinct concepts, and conflating them leads to poorly designed acceptance checks.
(source: *"[SWEBOK excerpt b586fdd39148fb34c49b]."*)

**2. Replace the fixed absolute threshold with a *relative* error check.**
The absolute error |x\* − x| is insensitive to the magnitude of the values being compared — it is too strict for large values and too loose for small ones. The relative error |x\* − x| / |x| normalises the discrepancy by the size of the true value and is therefore scale-independent.
(source: *"[SWEBOK excerpt c7ee85f3eab02e26f163]."*)

**3. Treat relative error as the preferred measure of error size.**
SWEBOK explicitly ranks relative error above absolute error for general use because it captures how significant the deviation is in proportion to the quantity being measured.
(source: *"[SWEBOK excerpt 297dadd84958fa3cc461]."*)

**4. Handle the zero case explicitly, because relative error is undefined there.**
When the expected value is exactly zero, dividing by it is undefined, so a relative threshold cannot be applied. A fallback strategy (e.g., a small absolute tolerance near zero, or a combined threshold) must be specified separately for that case.
(source: *"[SWEBOK excerpt c7ee85f3eab02e26f163]."*)

**5. Use the relative error threshold to determine how many significant digits are correct.**
Once a relative error bound *ε* has been chosen, it directly tells how many leading (significant) decimal digits of the computed result can be trusted: [SWEBOK excerpt cdafe08bad9eba82918c] when its relative error is less than 5 × 10^(−k−1).
(source: *"[SWEBOK excerpt 4d674c3f3cbb2cfca7c0]."*)

**6. Anchor the notion of "trusted digits" to significant figures, not to decimal places.**
Significant digits are counted from the first non-zero digit, not from the decimal point. A test tolerance expressed as a fixed decimal-place threshold (like 0.001) measures decimal-place agreement, not significant-digit agreement, and therefore behaves inconsistently across different value magnitudes.
(source: *"[SWEBOK excerpt f7f3a65aa84a447e276f]."*)

---

**Summary of the core fix:** Replace `|computed − expected| < 0.001` with `|computed − expected| / |expected| < ε` (for some chosen ε, e.g. 10⁻⁶ for six significant digits), handling the `expected = 0` case separately. The chosen ε then directly communicates — via the formula k significant digits ↔ relative error < 5 × 10^(−k−1) — exactly how many leading digits of the result are guaranteed to be correct.
