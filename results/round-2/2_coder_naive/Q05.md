### 1. Partition the input domain into equivalence classes — including both valid and invalid values — and pick at least one representative input from each class.

### 2. Choose test cases on or near the boundaries of the valid range, since faults tend to cluster at extreme values.

**Boundary Value Analysis** directly targets the edges of the numeric range, where bugs are most likely to hide.

(source: "[SWEBOK excerpt bedee61fb08d8b967278].")

### 3. Also include inputs just outside the valid range to test robustness in handling erroneous or unexpected input.

This is an extension of boundary value analysis called **robustness testing**.

---

### 4. Select a small but representative set of test inputs from the input domain rather than trying to test all possible values.

Exhaustive testing is impractical; the goal of specification-based techniques is to select a targeted subset that can detect specific categories of faults.

(source: "[SWEBOK excerpt 094d0a895b498b2baf0f].")

---

### 5. Consider supplementing with randomly chosen inputs from within the known input domain for broader automated coverage.

**Random Testing** can complement the above targeted approaches by sampling additional points from the domain.

(source: "[SWEBOK excerpt 7466320afd0b82fed0f0].")

---

### 6. When the function involves multiple numeric parameters, use combinatorial techniques to systematically cover combinations of values rather than testing each parameter in isolation.

**Combinatorial Test Techniques** (e.g., pairwise testing) address the explosion of possible combinations when multiple inputs exist.
