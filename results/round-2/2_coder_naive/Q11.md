## Categories of Changes Made to Software Already in Use

According to SWEBOK v4, software maintenance encompasses several distinct categories of changes, each distinguished by its purpose and trigger.

---

### 1. Corrective Maintenance
**Guideline:** Use corrective maintenance to fix faults discovered in the software after delivery — this is reactive in nature, responding to known defects that cause the software to behave incorrectly.

### 2. Adaptive Maintenance
**Guideline:** Use adaptive maintenance when the software's environment changes — such as changes to interfaced systems, hardware, or infrastructure — requiring the software to be modified to keep operating correctly in its new setting.

### 3. Perfective Maintenance
**Guideline:** Use perfective maintenance to improve or enhance the software based on user needs or quality goals, without necessarily fixing a fault. This includes adding user enhancements, improving documentation, and recoding for better performance or maintainability.

### 4. Preventive Maintenance
**Guideline:** Use preventive maintenance to proactively address latent faults or quality issues before they manifest as failures, thereby reducing the risk of future problems and preventing security threats.

### 5. Additive Maintenance
**Guideline:** Use additive maintenance — distinct from perfective maintenance — when the change involves relatively large additions of new functionality or features to improve software usability, performance, or other quality attributes after delivery, rather than small refinements.

### 6. Emergency Maintenance
**Guideline:** Treat emergency maintenance as a special, unscheduled form of corrective maintenance, applied only as a temporary measure to keep a system operational until a proper corrective fix can be implemented.
