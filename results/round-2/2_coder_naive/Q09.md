### CERT/CC Top 10 Software Security Practices

5. **Validate input.**
All input — from users, files, networks, or other software — must be validated before use to prevent injection attacks and other exploits.
(source: "[SWEBOK excerpt 069352d3c831bede393c].")

6. **Heed compiler warnings.**
Compiler warnings often point to latent bugs or unsafe code patterns that could be exploited; ignoring them increases risk.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 2. Heed compiler warnings.")

7. **Architect and design for security policies.**
Security must be built into the architecture and design of the software — not bolted on afterward.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 3. Architect and design for security policies.")

8. **Keep it simple.**
Unnecessary complexity increases the attack surface and makes vulnerabilities harder to find and fix.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 4. Keep it simple.")

9. **Default deny.**
Access and capabilities should be denied by default, and only explicitly granted when needed.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 5. Default deny.")

10. **Adhere to the principle of least privilege.**
Code (and the users/processes running it) should operate with the minimum privileges necessary to perform its function.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … [SWEBOK excerpt 95e3f394f6c21a8e46bd].")

11. **Sanitize data sent to other software.**
Data passed to other components, systems, databases, or external services must be sanitized to prevent injection flaws and cross-component exploits.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 7. Sanitize data sent to other software.")

12. **Practice defense in depth.**
No single security measure is sufficient. Layered, overlapping security controls should be used so that a failure in one layer does not expose the system.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 8. Practice defense in depth.")

13. **Use effective quality assurance techniques.**
Quality assurance methods — including testing, code review, and static analysis — help discover vulnerabilities before attackers can.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 9. Use effective quality assurance techniques.")

14. **Adopt a software construction security standard.**
Following a recognized secure coding standard (such as those published by CERT) provides a systematic baseline for avoiding known vulnerability classes.
(source: "[SWEBOK excerpt f52e1dc67381cb39c5fa]: … 10. Adopt a software construction security standard.")
