# Guidelines for Managing an Unfamiliar Third-Party API and an Uncertain Performance Target

## During Planning

1. **Treat both the unknown API and the uncertain performance target as explicit risk factors.** Identify them in a risk register, estimate their probability and potential impact, and develop mitigation strategies before work begins. Risk management should address software-unique aspects like risks related to quality requirements such as performance.
(source: Risk Management and Quality Assessment/Risk Management_ Identification, Analysis, and Mitigation Strategies.md)

2. **Use prototyping early to verify the technical feasibility of both the API integration and the performance target.** A prototype helps engineers check whether a candidate solution is technically feasible, and peer review of the prototype can also spur identification of further risks.
(source: "[SWEBOK excerpt 2470379ec97ce555faa8].")

3. **Quantify the performance requirement economically before freezing it.** A quality-of-service constraint like performance has a value curve with a "perfection point" (beyond which extra performance adds no benefit) and a "fail point" (below which the system has no value). The most cost-effective target is the point of maximum positive difference between value and cost to achieve it, not an arbitrary stated number.
(source: Requirements Engineering_ Elicitation, Analysis, and Specification/Requirements Engineering_ Viability, Verification, and Stakeholder Management/Performance Thresholds and Cost-Effective Quality Optimization/Cost-Effective Performance and Quality Trade-offs.md)

4. **State the performance requirement as a testable, quantified acceptance criterion, not a vague aspiration.** Each requirement should be unambiguous and testable, meaning compliance or noncompliance can be clearly demonstrated.
(source: Requirements Engineering_ Elicitation, Analysis, and Specification/Requirements Analysis and Refinement/Software Requirements Properties and Quality Criteria.md)
