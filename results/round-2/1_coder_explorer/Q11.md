### Question

What kinds of changes are made to software that is already in use, and what distinguishes each kind from the others?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
SWEBOK v4 identifies several distinct types of changes made to software already in use, each defined by *why* the change is needed. Corrective maintenance fixes existing faults; adaptive maintenance keeps software working as its environment (hardware, infrastructure, interfaced systems) changes; perfective maintenance enhances quality, performance, or documentation without fixing faults; additive maintenance adds large new features or functions; and emergency maintenance is an unscheduled, temporary fix applied urgently to keep a system running. The BoK also highlights that over 80% of maintenance effort goes to enhancing and adapting software — not simply fixing defects, contrary to popular belief.

# Guidelines

- **Corrective maintenance** addresses faults and latent defects already present in the software, and is one of the core reasons software is maintained. (source: `root/Software Testing, Operations, and Maintenance/Software Operations and Maintenance Practices/Software Maintenance Roles and Cost Distribution/Software Maintenance Activities and Cost Distribution.md` — "Correct faults and latent defects")

- **Adaptive maintenance** responds to changes in the external environment. The BoK cites the purpose: "[SWEBOK excerpt ebc3b37ef414b02f8fb9]." (source: same file as above)

- **Perfective maintenance** is "[SWEBOK excerpt 6e3893bacf78f98660e5]." (source: `root/Software Testing, Operations, and Maintenance/Software Operations and Maintenance Practices/Types of Software Maintenance Activities.md`)

- **Additive maintenance** differs from perfective in two respects: it provides new functions or features to improve software attributes, and it involves "[SWEBOK excerpt dfdfbf27ea4d241ee402]." (source: same file as above)

- **Emergency maintenance** is an "[SWEBOK excerpt 29afddbf422c4d134083]." It is distinguished by its urgency and its temporary, stop-gap nature. (source: same file as above)

- **Preventive/security maintenance** proactively addresses future risk: the BoK lists "prevent security threats" and "[SWEBOK excerpt 75e12e5f36a78364dbb3]" as explicit maintenance purposes. (source: `root/Software Testing, Operations, and Maintenance/Software Operations and Maintenance Practices/Software Maintenance Roles and Cost Distribution/Software Maintenance Activities and Cost Distribution.md`)

- Enhancement and adaptation dominate maintenance costs: "[SWEBOK excerpt 98572396286eced0251b]," correcting the misconception that maintenance is mainly about fixing defects. (source: same file as above)
