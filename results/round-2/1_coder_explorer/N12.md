### Question

A test accepts a computed result when its difference from the expected value is below 0.001, which is far too strict for values in the millions and far too loose for values around 0.0001. How should the discrepancy be measured instead, and how does that measure tell how many leading digits of the result can be trusted?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
A fixed absolute tolerance like 0.001 fails because the same numerical gap means very different things at different scales. The BoK prescribes using **relative error** — |x* − x| / |x| — instead, which it explicitly calls "[SWEBOK excerpt 09180dd579d1a2f529c4] relative error then directly determines how many leading digits are correct: an approximation has *k* significant decimal digits if and only if its relative error is less than 5 × 10^(−k−1).

# Guidelines

- **Replace absolute error with relative error.** The discrepancy should be measured as |x* − x| / |x|, not |x* − x|. (source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md` — *"[SWEBOK excerpt e34f7850b6927fbf9f5d]|"*)

- **Prefer relative error as the principal tolerance criterion.** The BoK states: *"[SWEBOK excerpt 297dadd84958fa3cc461]."* (source: same file)

- **Understand why absolute error is scale-blind.** The BoK shows: *"[SWEBOK excerpt 3baaec5a616a729ec42c]⁻⁶, [SWEBOK excerpt 8f40bc3ffa6de1a9ad8f]."* The same absolute gap is negligible at large scale but catastrophic at small scale. (source: same file)

- **Translate a relative error bound directly into trusted leading digits.** *"[SWEBOK excerpt d733fa16600e8d921702])."* Set your tolerance from however many correct leading digits you require. (source: same file)

- **Count significant digits from the first nonzero digit, not the decimal point.** *"[SWEBOK excerpt b0cbf7e40e6061f47ac9]."* Relative error handles this automatically; absolute error does not. (source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Significant Digits in Measurements.md`)

- **Distinguish accuracy from precision.** *"[SWEBOK excerpt b586fdd39148fb34c49b]."* A numerical acceptance test is measuring accuracy, to which relative error applies. (source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Fixed-Point Arithmetic and Numerical Precision.md`)
