### Question

How should I derive test cases for a component whose behavior depends on its current state and on the events it receives?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
For components whose behavior depends on current state and received events, SWEBOK v4 recommends **State Transition Testing**: represent the component as a Finite-State Machine, then derive a test suite that covers states and transitions at a chosen coverage level. This falls within specification-based (black-box) testing, complemented by model-based testing and scenario-based testing for validating behavioral requirements.

# Guidelines

- **Model the component as a Finite-State Machine (FSM).** State Transition Testing techniques are built around this model of the SUT. (source: `root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md` — *"Techniques based on Finite-State Machines… [SWEBOK excerpt e100766fea5ee2a192d1]."*)

- **Derive the test suite to cover states and transitions at a specified coverage level.** The choice of coverage level determines how thoroughly the state space and its transitions are exercised. (source: `root/Software Testing Methodologies and Techniques/Scenario-Based Testing for Requirements Validation.md` — *"the test [SWEBOK excerpt 1e051e7dde1a64e3a5e8]."*)

- **Use specification-based (black-box) techniques grounded in the SUT's input/output behavior.** State transition testing belongs to this family: test cases come from the behavioral specification, not from internal code. (source: `root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md`, §3.1 — *"in the specification-based [SWEBOK excerpt f5237fb14c87734fa3d6]."*)

- **Adopt model-based testing as the overarching framework.** When a behavioral model such as an FSM exists, model-based testing encompasses all techniques that use it. (source: `root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md`, §3 — *"model-based testing [SWEBOK excerpt a4f61e38cc73c9322c5a]."*)

- **Use scenario-based testing to validate state-dependent behavioral requirements.** Scenarios generate test cases focused on behavioral aspects and check requirements for consistency. (source: `root/Software Testing Methodologies and Techniques/Scenario-Based Testing for Requirements Validation.md`, §3.1.8 — *"[SWEBOK excerpt e41ffd571d00f5662528]."*)

- **Apply cause-effect graphing to identify relevant input conditions (causes) and output conditions (effects)** before building the FSM model. (source: `root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md` — *"[SWEBOK excerpt 86d9317a948fcaa65303]."*)
