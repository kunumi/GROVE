### Question

A function takes six configuration parameters, each with several possible values, and testing every possible mix of their values is too expensive. How should the test cases be derived?

### Answer

# Summary
When testing a function with six configuration parameters, exhaustive all-combinations testing is unnecessary. SWEBOK v4 describes a family of **combinatorial test techniques** — including pair-wise/t-wise testing and orthogonal array testing — that systematically derive a small test suite covering every combination of any *t* parameters. These are complemented by **equivalence partitioning** (to reduce values per parameter) and **boundary value analysis** (to focus on fault-prone extreme values), together with **decision tables** and **cause-effect graphing** for structured derivation.

- **Apply pair-wise (t-wise) testing**: "[SWEBOK excerpt 84129f160b87efa4ccba]."
