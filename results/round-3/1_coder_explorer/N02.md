### Question

A coding agent proposes splitting a large module into several networked services. Before anyone implements it, how can the team check whether this high-level structure will meet goals that pull against each other, such as response time, hosting cost and ease of future change?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
Before committing to a networked-services decomposition, the team should treat the competing quality goals (response time, hosting cost, modifiability) as Architecturally Significant Requirements (ASRs), then evaluate candidate structures using structured methods—chiefly ATAM—that explicitly surface trade-offs between those goals. The evaluation should rest on concrete Architecture Descriptions, be supported by architecture metrics and formal/simulation analysis for quantitative concerns, and be validated through architecture reviews and use-case walkthroughs, all before any implementation begins.
