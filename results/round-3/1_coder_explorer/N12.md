### Question

A test accepts a computed result when its difference from the expected value is below 0.001, which is far too strict for values in the millions and far too loose for values around 0.0001. How should the discrepancy be measured instead, and how does that measure tell how many leading digits of the result can be trusted?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
An absolute threshold like 0.001 is scale-dependent and thus unreliable across different magnitudes. The correct measure is **relative error** — `|x* − x| / |x|` — which scales with the true value and is explicitly described in SWEBOK as "[SWEBOK excerpt 09180dd579d1a2f529c4] number of trusted leading digits (significant digits) is then read directly from the relative error: a result has **k significant decimal digits** when its relative error is less than 5 × 10⁻⁽ᵏ⁺¹⁾, meaning the first k digits after the leading nonzero digit of the computed result agree with those of the true value.

# Guidelines

- **Replace absolute error with relative error.** The discrepancy between a computed value x* and the true value x should be measured as `|x* − x| / |x|` rather than `|x* − x|`. The BoK states: *"[SWEBOK excerpt 297dadd84958fa3cc461]."*
(source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md`)

- **Set the acceptance threshold in terms of relative error, not an absolute number.** Because relative error already accounts for the magnitude of x, the same threshold applies equally to values in the millions and to values around 0.0001.
(source: same file — "[SWEBOK excerpt 3baaec5a616a729ec42c]⁻⁶, [SWEBOK excerpt 8f40bc3ffa6de1a9ad8f].")

- **Read off trusted digits from the relative error: k significant decimal digits if and only if relative error < 5 × 10⁻⁽ᵏ⁺¹⁾.** A relative error of 5 × 10⁻⁷, for instance, guarantees 6 correct leading digits; requiring a relative error below 5 × 10⁻⁴ guarantees only 3.
(source: same file — "[SWEBOK excerpt e98f68a3670db66a99c0]⁻ᵏ⁻¹.")

- **Interpret significant digits structurally:** k significant digits means *"[SWEBOK excerpt 2ca9adccbb9e2c155966].
(source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Significant Digits in Measurements.md` — "[SWEBOK excerpt ddeb6a3fea1ba3e9820a].")

- **Note that relative error is undefined when x = 0.** The BoK explicitly states this assumption: "[SWEBOK excerpt e034ef87971721713ecf]."
(source: `Precision, Absolute Error, and Relative Error.md`)

- **Distinguish accuracy (closeness to the true value) from precision (repeatability).** Relative error measures accuracy. A test based on relative error checks whether the computed value agrees with the true value, not whether repeated runs agree with each other.
(source: `root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Fixed-Point Arithmetic and Numerical Precision.md` — "[SWEBOK excerpt b586fdd39148fb34c49b].")
