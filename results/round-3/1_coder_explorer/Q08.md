### Question

After each change to a system, how should the team decide what to test again, and at which point of the process?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
After each system change, the team should apply **regression testing** — selective retesting [SWEBOK excerpt 021f9937eefeac172cee] system still meets its requirements. Test case **selection, minimization, and prioritization** make this practical when full retesting is too expensive. Regression testing should run at all test levels (unit, integration, system), typically after integration testing and before deployment, and should be automated in Agile/DevOps/TDD environments where changes occur continuously.

# Guidelines

- **Use regression testing as the primary mechanism for retesting after changes** — it verifies [SWEBOK excerpt 19ea2fcfc60bb036ff4c]. (source: `root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md`)

- **Apply both functional and non-functional regression tests** — regression testing may cover [SWEBOK excerpt 6081dd06be3ad080f185], not just functional behavior. (source: `root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md`)

- **Use test case selection and minimization to keep regression testing practical** — selection, minimization, and prioritization reduce the size of the test suite re-executed after each change. (source: `root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md`)

- **Prioritize test cases to maximize fault detection rate** — prioritization schedules [SWEBOK excerpt dd8bd0bb133cd433eedf], code coverage, and reliability; similarity-based prioritization is widely adopted. (source: `root/Software Testing Levels, Objectives, and Approaches/Test Case Prioritization for Fault Detection.md`)

- **Accept a cost–assurance trade-off** — "[SWEBOK excerpt 164f0c3370a5c8da9469]." (source: `root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md`)

- **Apply regression testing at every test level** — it can be conducted at unit, integration, and system levels, not only at the end. (source: `root/Software Testing Levels, Objectives, and Approaches/Alpha, Beta, and Regression Testing Procedures.md`)

- **Time regression testing after integration and before deployment** — "[SWEBOK excerpt 302fdce151c0bdc54f71]." (source: `root/Software Testing Levels, Objectives, and Approaches/Regression Testing in Software Development.md`)

- **In DevOps/CI, perform regression testing continuously** — "[SWEBOK excerpt 368d0d5d949340799766]." (source: `root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Strategies Across Methodologies and Domains/Test Automation and Domain-Specific Testing Approaches.md`)

- **Run smoke testing first as a quick sanity check** — smoke testing (Build Verification Testing) ensures core functionalities work and the SUT is operational before full regression testing begins. (source: `root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Smoke Testing and Knowledge-Based Testing Approaches.md`)

- **Automate to manage regression risk** — "[SWEBOK excerpt 60175c6d5b01dd84f09f]," especially in continuous integration contexts. (source: `root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Strategies Across Methodologies and Domains/Testing Techniques Across Development Levels and Shift-Left Approaches.md`)

- **In shift-left development, focus regression at unit and integration levels using structure-based techniques** — regression is a primary internal code quality objective, targeted at unit and integration levels with structure-based techniques. (source: `root/Software Testing, Operations, and Maintenance/Testing Across Development Processes and Domains/Testing Aspects in Shift-Left Development.md`)

- **Reuse existing test cases to reduce retesting cost** — "reusability of test cases is pivotal in … regression testing … and [SWEBOK excerpt a7ace71c29882e121f03]." (source: `root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Test Planning and Reusability Strategy/Test Case Reusability in Software Development.md`)
