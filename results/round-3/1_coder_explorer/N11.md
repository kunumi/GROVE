### Question

Our orders table repeats the customer's name and address on every order row, and after a customer moves some rows show the old address while others show the new one. How should the tables be restructured, and what does that cost when querying the data?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
Your orders table suffers from data redundancy and data inconsistency — the exact problems that database normalization was designed to solve. The fix is to move customer name and address into a separate **Customers** table (linked by a key), progressively applying 1NF through 3NF/BCNF. The cost is that every query retrieving customer details now requires a JOIN, which increases processing time; if that overhead becomes unacceptable, selective de-normalization can trade data-integrity risk back for speed.
