### 1. Validate All Input
Every piece of data coming from external sources must be checked for validity before use. This is the first and most fundamental defence against injection attacks, buffer overflows, and many other vulnerabilities.

### 2. Heed Compiler Warnings
Compiler warnings often flag potential bugs and unsafe constructs that attackers can exploit. Treat warnings as errors and resolve them before shipping code.

### 3. Architect and Design for Security Policies
Security should be built into the design of a system, not bolted on afterward. The software's structure should reflect and enforce its security requirements from the start.

### 4. Keep It Simple
Complex code is harder to reason about, audit, and secure. Simplicity reduces the attack surface and the likelihood of introducing subtle vulnerabilities.

### 5. Default Deny
Access, permissions, and capabilities should be denied by default; they should only be granted explicitly. Code that starts from a "deny all" baseline limits the damage an attacker can do if a gap is found.
