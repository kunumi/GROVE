### Guidelines for Choosing Test Inputs for a Numeric Function with a Valid Range

---

**1. Partition the input domain into equivalence classes and select a representative value from each.**

Use equivalence partitioning to group inputs into subsets that are expected to be treated the same way. At minimum, define a class for valid inputs and one for invalid (out-of-range) inputs, then pick at least one representative from each class.

> (source: "[SWEBOK excerpt e279d64d08518504c456] [SWEBOK excerpt 1a60498744b577380a00].")

---

**2. Choose test cases on or near the boundaries of the valid range.**

Boundary Value Analysis (BVA) directs you to pick values exactly at and just inside or outside the range limits (e.g., minimum, maximum, min−1, max+1), because faults tend to cluster at extremes.

> (source: "[SWEBOK excerpt bedee61fb08d8b967278].")

---

**3. Also test inputs outside the valid range (robustness testing).**

Extend your boundary tests to include values clearly beyond the allowed range. This robustness testing verifies that the function handles unexpected or erroneous inputs gracefully.

> (source: "[SWEBOK excerpt ac52d3263555a546a515].")

---

**4. Use the input domain as the basis for any random test selection.**

If using random testing, the valid input domain must first be known and defined so that random points can be meaningfully drawn from it. Random testing offers a simple path to automation and can be enhanced with adaptive strategies.

> (source: "[SWEBOK excerpt 2e0f1efa93239b85b4bd].")

---

**5. Use specification-based (black-box) techniques, selecting a few targeted inputs to detect specific fault categories.**

The goal of specification-based techniques is to select a small but effective set of test cases from the input domain capable of detecting specific categories of faults (domain errors), and to verify that the function returns the required output for inputs within range.

> (source: "[SWEBOK excerpt 094d0a895b498b2baf0f].")

---

**6. Consider combining techniques, since different selection criteria yield vastly different levels of effectiveness.**

No single technique is universally best. Combining approaches (e.g., equivalence partitioning with boundary value analysis, or deterministic with random) improves fault detection, as different techniques expose different problems.

> (source: "[SWEBOK excerpt db510fda32d0332e7b10].")

---

**7. Ensure test inputs include both valid and invalid cases, verifying that out-of-range values trigger appropriate error handling.**

Both valid inputs and out-of-range (invalid) inputs must be covered. Invalid inputs should trigger an error message or error processing, so tests must confirm this behavior as well.

> (source: "[SWEBOK excerpt c3d87fbc75fe24a6c7d5].")
