### CERT/CC Top 10 Software Security Practices

5. **Validate input.**
   All input from external sources must be checked before use to prevent injection, overflow, and other input-based attacks.
   (source: *"[SWEBOK excerpt 3e71e725c4f83e41d6db]."*)

6. **Heed compiler warnings.**
   Compiler warnings often flag code patterns that are known to introduce vulnerabilities and should not be ignored.
   (source: *"2. Heed compiler warnings."*)

7. **Architect and design for security policies.**
   Security must be built into the architecture and design of the system, not added as an afterthought.
   (source: *"3. Architect and design for security policies."*)

8. **Keep it simple.**
   Complexity is the enemy of security; simpler code is easier to reason about and less likely to contain hidden vulnerabilities.
   (source: *"4. Keep it simple."*)

9. **Default deny.**
   Access should be denied by default; permissions must be explicitly granted rather than assumed.
   (source: *"5. Default deny."*)

10. **Adhere to the principle of least privilege.**
    Code and components should operate with only the minimum permissions necessary to perform their function.
    (source: *"[SWEBOK excerpt 95e3f394f6c21a8e46bd]."*)

11. **Sanitize data sent to other software.**
    Data passed to other systems, libraries, or components must be cleaned to prevent injection and similar attacks.
    (source: *"7. Sanitize data sent to other software."*)

12. **Practice defense in depth.**
    Multiple, overlapping security controls should be used so that if one layer fails, others still protect the system.
    (source: *"8. Practice defense in depth."*)

13. **Use effective quality assurance techniques.**
    Techniques such as code reviews, static analysis, unit testing, and security-oriented reviews help catch vulnerabilities before deployment.
    (source: *"9. Use effective quality assurance techniques."*)

14. **Adopt a software construction security standard.**
    Following a recognized secure coding standard (e.g., CERT C, CERT Java) provides consistent, proven practices for avoiding known vulnerability classes.
    (source: *"10. Adopt a software construction security standard."*)
