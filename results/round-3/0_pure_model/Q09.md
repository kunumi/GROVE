### Question

What general practices should developers follow when writing code so that attackers cannot exploit it?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

Here are general practices developers should follow when writing code to prevent exploitation by attackers:

1. **Validate all inputs** – Never trust data from external sources. Validate, sanitize, and constrain all inputs to ensure they conform to expected formats, lengths, and types before processing. (source: "All input data should be validated to ensure it conforms to the expected format")

2. **Avoid buffer overflows** – Be careful with memory allocation and array bounds. Use safe library functions and always check that data written to a buffer does not exceed its allocated size. (source: "Buffer overflows are one of the most common and dangerous security vulnerabilities")

3. **Use the principle of least privilege** – Code should run with the minimum permissions necessary to perform its function, limiting the damage that can be done if it is compromised. (source: "software should operate with the least set of privileges necessary to accomplish the required functions")

4. **Avoid hardcoded credentials and secrets** – Passwords, keys, and tokens should never be embedded directly in source code, as they can be discovered through code inspection or reverse engineering. (source: "Sensitive information such as passwords should not be hardcoded in software")

5. **Handle errors and exceptions securely** – Error messages should not reveal sensitive system information to users. Catch and handle exceptions gracefully to prevent information leakage. (source: "Error messages should not reveal information that could be useful to an attacker")

6. **Use secure cryptographic practices** – Use well-established, up-to-date cryptographic algorithms and avoid implementing custom cryptography, which is prone to errors. (source: "Developers should use established cryptographic libraries rather than creating their own")

7. **Avoid injection vulnerabilities** – Use parameterized queries or prepared statements rather than constructing queries or commands by concatenating user-supplied input, to prevent SQL injection and similar attacks. (source: "Input validation and the use of parameterized queries can prevent injection attacks")

8. **Keep security in mind during design, not just implementation** – Security should be considered from the earliest stages of software development, not added as an afterthought. (source: "Security should be considered throughout the software development lifecycle, not just at the end")

9. **Conduct code reviews with a security focus** – Peer review and static analysis tools should be used to identify potential security flaws in code before it is deployed. (source: "Code reviews and static analysis can identify security vulnerabilities in source code")

10. **Keep third-party libraries and dependencies up to date** – Vulnerabilities in dependencies can be exploited; developers should monitor and update them regularly. (source: "Third-party components should be kept up to date to avoid known vulnerabilities")
