# Guidelines
- Use assertions — executable predicates placed inside a routine — to perform runtime checks of assumptions about inputs and program state. [SWEBOK excerpt 4b5d09b3a87e6f492d8f] and help flush out mismatched interface assumptions quickly. (source: root/Software Construction Techniques and Practices/Parameterization, Templates, Generics, and Assertions.md; root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md) [JEV 0.95]
- Apply Design by Contract: include explicit preconditions (what the caller must guarantee) and postconditions (what the routine guarantees in return) for each routine. Each routine or class is then [SWEBOK excerpt 3248db7c549fd555b194], precisely specifying its semantics and clarifying its behavior. (source: root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md; root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md) [JEV 0.97]
- Practice defensive programming: [SWEBOK excerpt e9abc85349cc38f7a2e7] by checking the values of all input parameters and deciding in advance [SWEBOK excerpt 7982520cf6f2b2330cf6]. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md; root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md) [JEV 0.96]
- Compile assertions into the code at development time and compile them out of the production build so they do not degrade runtime performance while still surfacing assumption violations during development and testing. (source: root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md) [JEV 0.97]
- Handle [SWEBOK excerpt 517202e3a3ee07b76140]) — explicitly in the coding activity. Techniques include [SWEBOK excerpt fab09da3601a283baf81]. (source: root/Software Construction Techniques and Practices/Software Coding and Construction Testing Practices.md; root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
- Use exception handling (throw/try-catch) [SWEBOK excerpt faa5a8a24fd72e5b9ae1]. Design exception-handling policies carefully: include [SWEBOK excerpt e56492e15b911c91a518], avoid empty catch blocks, know the exceptions that library code throws, and standardize the program's use of exceptions. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.97]
- Prevent code-level security breaches caused by unchecked inputs — such as buffer overflows or array-index-bounds violations — as part of the routine coding activity. (source: root/Software Construction Techniques and Practices/Software Coding and Construction Testing Practices.md) [JEV 0.97]
- Combine assertions and defensive programming with other construction-quality techniques — unit testing, test-first development, code inspections, technical/security reviews, and static analysis — to ensure that assumption violations and invalid-input paths are caught early. (source: root/Software Construction Techniques and Practices/Construction Quality Techniques and Practices.md) [JEV 0.94]
