- Partition the input domain into equivalence classes (valid and invalid) and select at least one representative test case from each class. For a numeric range, this means at minimum one value inside the valid range, one below it, and one above it. - Extend boundary value testing with robustness testing by also choosing test cases outside the valid input domain, to verify the program handles unexpected or erroneous inputs correctly. (source: root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.97]
- Include test cases specifically designed to force exceptions, such as overflow or underflow conditions, to verify that the function can manage predefined numeric error conditions and generate appropriate error messages. (source: root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Exception Testing and Error Handling in Software Testing.md) [JEV 0.96]
- Use combinatorial test techniques (e.g., pair-wise testing or all-combinations testing) to systematically derive test cases that cover specific parameter values or conditions when multiple numeric inputs interact. - Supplement deterministic (specification-driven) test selection with randomly drawn inputs from the input domain. Random testing provides a simple approach to automation and can expose faults that structured techniques miss; enhanced forms such as adaptive random testing can further direct sampling. - Combine specification-based (black-box) and structure-based (white-box) test case selection approaches, [SWEBOK excerpt 850132b272f72b31e5df], complementing each other.
