# Guidelines
- Replace the fixed absolute threshold with a relative-error check. The absolute error of an approximation x* to a true value x is |x* − x|, but the relative error is |x* − x| / |x|. Because the relative error normalises the discrepancy by the size of the true value, it is scale-independent and remains meaningful whether the values are in the millions or near zero — unlike a fixed tolerance such as 0.001, which is simultaneously too tight for large values and too loose for small ones. The BoK states: '[SWEBOK excerpt 297dadd84958fa3cc461].' (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.89]
- Understand the difference between accuracy and precision before choosing a tolerance. [SWEBOK excerpt 1f471aaf68aafaaa417c], while precision [SWEBOK excerpt 6a95d65282980f06335d]. A test threshold should target the required accuracy (agreement with truth), not just precision (repeatability), so the tolerance must be set relative to the magnitude of the true value. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Fixed-Point Arithmetic and Numerical Precision.md) [JEV 0.68]
- Use the relative error to determine how many leading (significant) digits of the result can be trusted. [SWEBOK excerpt 94dcfaf34a6455ae8383] less than 5 × 10^(−k−1). Equivalently, [SWEBOK excerpt 725fb0910000ec9b0406] the true value x. This gives a direct, scale-independent reading of correctness: a relative error below 5 × 10^−4 means the result is correct to three significant digits, regardless of whether those digits represent thousands or millionths. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md; root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Significant Digits in Measurements.md) [JEV 0.96]
- Express the acceptance criterion as a maximum permitted relative error, not a fixed absolute difference. For example, the BoK illustrates that the absolute error of approximating 1,000,001 by 1,000,000 is 1 — which would fail a 0.001 absolute test — yet the relative error is only 10^−6, indicating the approximation is correct to six significant digits. Conversely, approximating 11 by 10 also gives an absolute error of 1 but a relative error of 0.1, indicating only about one significant digit, which a 0.001 absolute threshold would not catch if both values happened to be small. Setting the threshold as a relative error prevents both kinds of mis-classification. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.88]
- When reporting or recording measured results alongside the test, count and state the number of significant digits. [SWEBOK excerpt 11fbdd31787e7073109f] [SWEBOK excerpt 74eb3ea8534ba215b83c]. This practice makes the precision of both the expected value and the computed result explicit, enabling the test threshold to be aligned with the actual precision of the reference data rather than an arbitrary fixed constant. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Significant Digits in Measurements.md) [JEV 0.78]
