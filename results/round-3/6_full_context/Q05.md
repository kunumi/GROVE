How should test inputs be chosen for a function that accepts numeric values within a valid range?

### Answer

Here are guidelines for choosing test inputs for a function that accepts numeric values within a valid range, drawn from the SWEBOK:

1. **Partition the input domain into equivalence classes** — divide inputs into subsets where all values in a class are expected to behave the same way, then select a representative test case from each class, including both valid and invalid inputs.
(source: Software Requirements_ Foundations and Engineering Practices/Software Requirements Engineering Fundamentals/Guide to the Software Engineering Body of Knowledge V4/SWEBOK Guide Version 4.0 Overview/SWEBOK Guide Version 4.0a Table of Contents.md — specifically the testing section; more precisely from the text: "[SWEBOK excerpt e279d64d08518504c456] [SWEBOK excerpt 9fbbc794267d8d3b05cc].")

2. **Choose test cases at [SWEBOK excerpt 3fc837c43498156c3276]** — many faults tend to concentrate near extreme values, so test cases should be selected on or near the boundaries of valid ranges.
(source: "[SWEBOK excerpt bedee61fb08d8b967278].")

3. **Include out-of-range (robustness) inputs** — extend boundary value analysis by also choosing test cases outside the input domain to test how the function handles unexpected or erroneous inputs.
(source: "[SWEBOK excerpt ac52d3263555a546a515].")

4. **Use combinatorial test techniques to cover combinations of parameter values** — systematically derive test cases that cover specific combinations of values, such as pairwise testing, to ensure interactions between parameters are exercised.
(source: "[SWEBOK excerpt 06e9858a17d740b5db06].")

5. **Apply random testing within the known input domain** — randomly select inputs from within the domain as a relatively simple approach to test automation, potentially enhanced with adaptive strategies.
(source: "[SWEBOK excerpt a6fed37ec9a8639774a6].")

6. **Use forced exception test cases** — specifically construct inputs that are designed to trigger error conditions such as overflow, underflow, or out-of-range exceptions to verify the function handles them correctly.
(source: "[SWEBOK excerpt c5e355048592b5094412].")

7. **Ensure that adequacy criteria guide when enough tests have been selected** — use a test selection criterion to determine whether the chosen test cases provide sufficient coverage for the specified purpose, to avoid both under-testing and wasteful over-testing.
(source: "[SWEBOK excerpt 334409fde3252bc44f37].")
