# Strategies for Runtime Error Tolerance in Software

Based on the SWEBOK, here are guidelines for keeping software operational when runtime errors occur:

## Fault Tolerance Techniques

1. **Back up and retry** — When an error is detected, save state and attempt the operation again before failing.
(source: Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md)

2. **Use auxiliary code** — Provide alternative code paths that activate when the primary code path fails.
(source: Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md)

3. **Use voting algorithms** — Run multiple redundant computations and select the result agreed upon by the majority.
(source: Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md)

4. **Replace [SWEBOK excerpt f660d205c9fd6b796539]** — Substitute a safe placeholder value so execution can continue rather than halt.
(source: Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md)

## Error and Exception Handling

5. **Return a neutral value** — When a function encounters bad input or an error condition, return a value that is known to be safe and harmless.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

6. **Substitute the next piece of valid data** — Rather than stopping, skip the erroneous data item and continue processing with the next valid one.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

7. **Log a warning message** — Record the error in a log so it can be investigated later, while allowing execution to continue.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

8. **Return an error code** — Signal the error to the caller rather than crashing, allowing the calling code to decide how to respond.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

9. **Use try-catch blocks with meaningful exception messages** — Catch exceptions at appropriate levels and include [SWEBOK excerpt e56492e15b911c91a518].
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

10. **Avoid empty catch blocks** — Silently swallowing exceptions hides errors; each catch block should take a meaningful action.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

11. **Know the exceptions the library code throws** — Anticipate failure modes from third-party libraries so the software can handle them gracefully.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

12. **Build a centralized exception reporter** — Consolidate exception handling logic so the response to errors is consistent across the codebase.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

13. **Standardize the program's use of exceptions** — Apply uniform conventions across the codebase so exceptions are handled predictably everywhere.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md)

## Defensive Programming

14. **Use assertions to check input values** — Place executable predicates at routine boundaries to detect invalid states before they cause failures deeper in the program.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md)

15. **Check the values of all input parameters and decide how to handle bad inputs** — Explicitly validate every input at the boundary of a routine so invalid data is caught early.
(source: Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md)

16. **Restore the state before the erroneous process began, then terminate gracefully** — If an error cannot be recovered safely, roll back to a known-good state rather than leaving the system in a corrupted condition.
(source: Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md)
