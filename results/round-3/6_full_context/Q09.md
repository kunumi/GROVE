Based on the SWEBOK passages I read, here are the guidelines developers should follow when writing code to prevent attackers from exploiting it:

1. **Validate all input.** Ensure that any data entering the system is checked for validity before processing.

2. **Heed compiler warnings.** Do not ignore warnings generated during compilation, as they may signal potential vulnerabilities.
(source: Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Top 10 Software Security Practices.md)

3. **Architect and design for security policies.** Security should be a primary consideration during the design phase, not an afterthought.
(source: Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Top 10 Software Security Practices.md)

4. **Keep it simple.** Complexity increases the attack surface; simpler code is easier to reason about and audit for vulnerabilities.
