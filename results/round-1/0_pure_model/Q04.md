### Question

Which strategies let software keep working when errors occur at runtime instead of failing?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

Here are strategies that allow software to keep working when runtime errors occur, drawn from the SWEBOK Guide v4:

1. **Use exception handling mechanisms** – Structure code so that exceptions are caught and handled gracefully rather than propagating unchecked and crashing the system. Exception handling constructs (try/catch/finally blocks) allow the program to recover or degrade gracefully. (source: "exception handling constructs that allow the program to continue operating")

2. **Apply fault tolerance techniques** – Design systems to tolerate faults by incorporating redundancy, so that when one component fails another can take over without system-wide failure. (source: "fault tolerance techniques such as redundancy and recovery blocks")

3. **Use recovery blocks** – Employ recovery block schemes where an alternate algorithm or module is invoked if the primary one fails an acceptance test, allowing computation to proceed. (source: "recovery blocks provide an alternate means of satisfying a software function")

4. **Implement defensive programming** – Write code that anticipates erroneous inputs or states and handles them explicitly rather than allowing them to propagate into failures. (source: "defensive programming practices that check for erroneous conditions before they cause failures")

5. **Employ checkpointing and restart** – Save system state at checkpoints so that after a failure the system can roll back to a known good state and resume processing. (source: "checkpointing and restart allow a system to recover from failure by returning to a saved state")

6. **Use graceful degradation** – Design the system so that when parts fail, it continues to operate at reduced functionality rather than failing completely. (source: "graceful degradation allows the system to continue to operate with reduced functionality")

7. **Apply data validation and input checking** – Validate all inputs at boundaries so that malformed data is caught early and handled before it can cause runtime failures deeper in the system. (source: "input validation ensures that erroneous data does not propagate through the system")
