### Question

How should test inputs be chosen for a function that accepts numeric values within a valid range?

### Answer

Here are guidelines for choosing test inputs for a function that accepts numeric values within a valid range:

1. **Test values at the lower boundary of the valid range.** Boundary values are classic error-prone points and should always be included as test inputs. (source: "test cases are chosen at the boundaries of the input domain")

2. **Test values at the upper boundary of the valid range.** Similarly, the maximum valid value should be explicitly tested, as errors frequently occur at the upper edge of a range. (source: "test cases are chosen at the boundaries of the input domain")

3. **Test values just below the lower boundary (invalid input).** Testing one unit below the minimum checks that the function correctly rejects out-of-range values on the lower side. (source: "just below and just above the boundaries of valid ranges")

4. **Test values just above the upper boundary (invalid input).** Testing one unit above the maximum verifies that the function correctly rejects out-of-range values on the upper side. (source: "just below and just above the boundaries of valid ranges")

5. **Test a nominal (typical) value well within the valid range.** At least one representative value from the interior of the valid range should be tested to confirm normal operation. (source: "a value within the class to represent the entire equivalence class")

6. **Partition the input domain into equivalence classes and select one representative from each class.** Valid and invalid ranges each form equivalence classes; testing one value per class reduces redundancy while maintaining coverage. (source: "equivalence partitioning divides the input domain into classes of data from which test cases can be derived")

7. **Test special or singular values such as zero if it lies within or at the boundary of the range.** Special numeric values (zero, negative numbers at boundaries) are common sources of defects. (source: "special values such as zero or empty string should also be considered")
