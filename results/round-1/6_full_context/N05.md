### Question

A customer reports a defect in the executable we shipped to them two years ago, and to investigate it we need that very same executable back, byte for byte, but the toolchain and third-party libraries on our machines have been upgraded since then. What should the team have been tracking and preserving so that this would be possible?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

Here is a list of guidelines the team should have been following to make exact reproduction of a shipped executable possible:

1. **Place all source code under version control and preserve it for each release.** The team should be able to retrieve the exact source code corresponding to any released version. (source: Software Maintenance and Configuration Management/Software Configuration Management Planning and Implementation/Software Change Management and Version Control/Source Code Version Control and Management.md)

2. **Track and preserve the specific versions of all build tools — compilers, linkers, assemblers — used for each release, keeping them under SCM control.** "[SWEBOK excerpt e082f1c815b2042b56a6]." (source: Software Maintenance and Configuration Management/Software Configuration Management Planning and Implementation/Software Configuration Management Tools and Processes/Software Build Tools and Version Control Management.md)

(source: Software Maintenance and Configuration Management/Software Configuration Management Planning and Implementation/Software Configuration Management Tools and Processes/In-Process Audits and Software Release Management.md)
