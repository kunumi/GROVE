# Guidelines
- Replace the fixed absolute tolerance with a relative error measure. Relative error is defined as |x* − x| / |x|, [SWEBOK excerpt 7454b7d6506d5d7642c4] magnitude of the true value. Unlike a fixed threshold, this measure scales automatically with the size of the value being tested — making the same proportional demand whether values are in the millions or near zero. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.88]
- Understand that absolute error alone is not a reliable yardstick: the same absolute error of 1 represents a relative error of only 10⁻⁶ when the true value is 1,000,001, but a relative error of 0.1 when the true value is 11. Using relative error instead gives an intuitive and scale-independent picture of how close the approximation actually is. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.97]
- Prefer relative error as the standard measure of approximation quality. The BoK states explicitly that '[SWEBOK excerpt 08a637ab2472165ebfc5].' (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.97]
- Use relative error to determine how many leading significant digits of a result are correct. [SWEBOK excerpt e4bb630efbfcf7f6de55] and only if its relative error is less than 5 × 10^(−k−1). For example, a relative error below 5 × 10⁻⁴ guarantees three correct significant digits, regardless of the scale of the numbers involved. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.97]
- Understand what significant digits mean in practice: [SWEBOK excerpt 5b77646556b281e7ad1c] — specifically, [SWEBOK excerpt 028d3595b8100cfdfeca] match those of x. A tighter relative error threshold implies more correct leading digits; a looser one implies fewer. Set the acceptance threshold accordingly. (source: root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Significant Digits in Measurements.md; root/Foundations of Mathematics and Computational Systems/Numerical Methods, Algebra, and Calculus Foundations/Numerical Precision and Error Measurement/Precision, Absolute Error, and Relative Error.md) [JEV 0.94]
- Distinguish accuracy from precision when specifying numeric test criteria. Accuracy is the closeness of a computed value to the true value; precision is the closeness of repeated computed values to each other. Numeric test oracles should primarily target accuracy (via relative error) while precision addresses repeatability.
