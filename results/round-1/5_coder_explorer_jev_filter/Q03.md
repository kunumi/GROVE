# Guidelines
- Design exception-handling policies carefully and standardize the program's use of exceptions, rather than leaving exception handling ad hoc. This includes knowing which exceptions library code throws and potentially building a centralized exception reporter. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
- Always include [SWEBOK excerpt e56492e15b911c91a518], so that the cause of an abnormal condition can be diagnosed and acted upon. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
- Avoid empty catch blocks. When an exception is caught, the erroneous condition should be processed or control returned to the calling routine in a meaningful way. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
- Consider several alternative error-handling techniques depending on context: [SWEBOK excerpt fab09da3601a283baf81]. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.96]
- Use assertions—executable predicates placed in a program—to check for errors, especially in high-reliability programs. Assertions help flush out mismatched interface assumptions and errors introduced during code modification. (source: root/Software Construction Techniques and Practices/Parameterization, Templates, Generics, and Assertions.md; root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md) [JEV 0.95]
- Apply Design by Contract: specify preconditions and postconditions for each routine so that each routine or class forms [SWEBOK excerpt 13c5545a4a774df8cb56], improving construction quality and clarifying behavior under abnormal conditions. (source: root/Software Construction Techniques and Practices/Assertions and Design by Contract in Programming.md; root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md) [JEV 0.96]
- Practice defensive programming: protect routines from invalid inputs by checking the values of all input parameters and deciding in advance how to handle bad inputs. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Design by Contract and Defensive Programming.md) [JEV 0.98]
- Apply fault tolerance techniques to increase software reliability: detect errors, then recover from them or contain their effects if recovery is not possible. Common [SWEBOK excerpt f641518346288cdd4f30] with [SWEBOK excerpt 816c3a55755c2c58f38f]. (source: root/Software Construction Techniques and Practices/Fault Tolerance Techniques and Executable Models.md) [JEV 0.96]
- Recognize error and exception handling as a first-class design concern—alongside data persistence, distribution, and event handling—addressing [SWEBOK excerpt 9125b3302ad167c501cc] at the architecture level. (source: root/Software Design Concerns, Documentation, and Modeling/Software Design Concerns and Architectural Patterns.md) [JEV 0.90]
- Use the throw/try-catch structure as the basic mechanism for signaling and handling exceptions: a routine throws a detected exception, and a try-catch block catches it to [SWEBOK excerpt b390e69eb0d31053bee7] caller. (source: root/Software Construction Techniques and Practices/Contract Design and Error Handling Strategies/Error Handling, Exception Handling, and Fault Tolerance.md) [JEV 0.98]
