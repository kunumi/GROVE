# Guidelines
- Validate all input: Ensure that every piece of input entering the program is checked and validated before use. This is CERT/CC's first-ranked software security practice, as untrusted or malformed input is a primary vector for exploitation. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Top 10 Software Security Practices.md) [JEV 0.93]
- Heed compiler warnings: Pay attention to and resolve warnings generated by the compiler. Compiler warnings often flag code patterns that can lead to exploitable vulnerabilities and should not be ignored. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md) [JEV 0.96]
- Architect and design for security policies: Security should be built into the architecture and design of the software from the start, not bolted on later. The Secure Development Life Cycle (SDLC) views security holistically and ensures it is inherent in design and development. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Integration and Evaluation Standards/Security Engineering and Secure Development Life Cycle.md) [JEV 0.97]
- Keep it simple: Complexity is the enemy of security. Simple designs are easier to reason about, audit, and secure. Overly complex code is harder to analyze for vulnerabilities. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md) [JEV 0.80]
- Default deny: Access should be denied by default. Only explicitly permitted actions or resources should be granted, reducing the attack surface if any part of the program is compromised. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md) [JEV 0.91]
- Adhere to the principle of least privilege: Structure the code [SWEBOK excerpt 78675ff8d8cfe6b9460d] isolated into modules. Those [SWEBOK excerpt 915f9e49517a362ec847]. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices for Software Development.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Software Construction Security and Privilege Management.md; root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.97]
- Sanitize data sent to other software: Any data passed to external systems, libraries, or components must be properly sanitized to prevent injection attacks and unintended behavior. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices for Software Development.md) [JEV 0.87]
- Practice defense in depth: Layer multiple security controls so that if one fails, others remain in place. No single security measure should be the sole barrier against attackers. (source: root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md) [JEV 0.86]
- Use effective quality assurance techniques: Apply rigorous QA methods — including testing and code review — throughout development to catch and eliminate security flaws before they can be exploited. (source: root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md) [JEV 0.85]
- Adopt a software construction security standard: Follow an established, recognized coding security standard to ensure consistent, proven practices are applied across all code written in the project. (source: root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md) [JEV 0.96]
- Validate all program assumptions: Ensure that any assumptions embedded in the code are explicitly validated at runtime. If validation is not possible, document the assumptions so installers and maintainers understand which assumptions attackers will try to invalidate. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.97]
- Do not share objects in memory with other programs: Ensure the program does not share memory objects with any other program, preventing attackers from using shared memory as an attack vector. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.98]
- Check every function's error status: Never ignore return codes or error status values. If an error could affect security, restore the system to its pre-operation state and terminate rather than continuing in a potentially compromised state. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Secure Module Design and Error Handling Principles.md) [JEV 0.97]
- Conduct threat modeling during design: Developers should perform threat modeling to illustrate how a system could be attacked, then specify security design mitigations. This clarifies security considerations and determines the specific implementation steps needed. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Cryptographic Controls and Secure Software Construction.md) [JEV 0.97]
- Apply security patterns: Use well-proven, generic security patterns to address recurring security problems in specific contexts, ensuring that established solutions are applied rather than inventing new, potentially flawed approaches. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Cryptographic Controls and Secure Software Construction.md) [JEV 0.94]
- Build security in from the start — not as an afterthought: Security must be integrated throughout the software engineering process (SDLC). Making security an afterthought in production is costlier and less effective than integrating it from the earliest phases. (source: root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Integration and Evaluation Standards/Security Engineering and Secure Development Life Cycle.md) [JEV 0.96]
