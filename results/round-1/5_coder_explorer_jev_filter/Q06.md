# Guidelines
- Use combinatorial test techniques to systematically derive test cases that cover specific parameters and their values, rather than attempting exhaustive coverage of all possible combinations. (source: root/Software Testing Methodologies and Techniques/Combinatorial Test Techniques Overview.md) [JEV 0.79]
- Apply Pair-Wise (All-Pairs) Testing: derive test cases by combining the values of every pair of input parameters. This technique — also known as orthogonal array testing (OAT) — dramatically reduces the number of test cases while still covering all two-way interactions between parameters. (source: root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing and Decision Tables.md; root/Software Testing Methodologies and Techniques/Combinatorial Test Techniques Overview.md) [JEV 0.90]
- Consider t-wise testing (a generalisation of pair-wise) when broader interaction coverage is needed: instead of covering only pairs, every possible combination of t input parameters is exercised, allowing more than one pair to be derived per test case while still avoiding full enumeration. (source: root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing and Decision Tables.md) [JEV 0.92]
- Apply Equivalence Partitioning before choosing values: partition each parameter's input domain into equivalence classes based on a specified criterion (e.g., valid vs. invalid inputs, control flow, data flow), then select one representative value per class. This reduces the number of distinct values to combine without losing fault-detection power. (source: root/Software Testing Methodologies and Techniques/Software Testing Approaches and Techniques/Classification and Specification-Based Testing Techniques.md; root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.89]
- Apply Boundary Value Analysis when selecting representative values from each equivalence class: choose values on or near the boundaries of each parameter's domain, because [SWEBOK excerpt 44266d1663bca03e93fd]. (source: root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md) [JEV 0.95]
- Use Decision Tables to represent logical relationships between the configuration parameters (conditions) and expected outcomes (actions), and then systematically derive test cases from [SWEBOK excerpt 584648498d3f007b3eb1]. (source: root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing and Decision Tables.md; root/Software Testing Methodologies and Techniques/Systematic Test Case Derivation and Combinatorial Methods/Combinatorial Testing for Knowledge Representation and Documentation.md) [JEV 0.94]
- Use Cause-Effect Graphing to model logical relationships between input conditions (causes) and outputs (effects), identify the relevant input conditions, and explore the possible combinations of input conditions systematically to derive test cases. (source: root/Software Testing Methodologies and Techniques/Cause-Effect Graphing Techniques.md; root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md) [JEV 0.94]
- Combine functional (specification-based / black-box) and structural (white-box) techniques where needed; the two approaches are complements, using different information sources and highlighting different problems, and can be combined subject to budgetary constraints. (source: root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Combining Functional and Structural Testing Techniques.md) [JEV 0.96]
