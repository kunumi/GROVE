## Strategies for Keeping Software Running When Runtime Errors Occur

### 1. **Defensive Programming — Validate All Inputs**
Protect every routine from being broken by invalid inputs. Check the values of all input parameters and decide how to handle bad inputs before they can cause a failure.
> (source: *"[SWEBOK excerpt edaaca9c62404676ff9e]."*)

---

### 2. **Return a Neutral / Safe Value**
When an error is detected, return a neutral or harmless value so the program can continue processing instead of crashing.
> (source: *"[SWEBOK excerpt 25fb1a8cce8efbace92b]."*)

---

### 3. **Substitute the Next Piece of Valid Data**
When a particular data item is erroneous, skip it and continue with the next valid data item, keeping the program in operation.
> (source: *"[SWEBOK excerpt 25fb1a8cce8efbace92b]."*)

---

### 4. **Log a Warning Message**
Instead of halting execution, record the problem in a log and allow the program to continue. This preserves availability while maintaining a trace of what went wrong.
> (source: *"[SWEBOK excerpt 25fb1a8cce8efbace92b]."*)

---

### 5. **Return an Error Code**
Signal the error to the caller by returning an error code, allowing the calling code to decide how to respond rather than terminating the program immediately.
> (source: *"[SWEBOK excerpt 25fb1a8cce8efbace92b]."*)

---

### 6. **Exception Handling with Try-Catch Blocks**
Use structured exception handling: a routine throws [SWEBOK excerpt 50348ecb89afee4e470f] catches it in a try-catch block. The block can [SWEBOK excerpt c1de2b80a401caa76c67], letting execution continue.
> (source: *"[SWEBOK excerpt aa95fcd1c82d33a12fdb] try-catch [SWEBOK excerpt 980c1713bcc05a3281c2]."*)

---

### 7. **Follow Sound Exception-Handling Policies**
Design exception-handling carefully: include all information that led to the exception in the message, avoid empty catch blocks, know the exceptions library code throws, build a centralized exception reporter, and standardize the program's use of exceptions.
> (source: *"[SWEBOK excerpt 8a98e7d1cb740854b979]."*)

---

### 8. **Back Up and Retry**
When an error occurs, save state and retry the operation. This is one of the core fault-tolerance strategies that allows software to recover without failing.
> (source: *"[SWEBOK excerpt 7c7c13df07628c3c7d07]."*)

---

### 9. **Use Auxiliary Code and Voting Algorithms**
Employ redundant or alternative code paths that produce results independently; compare the results using a voting algorithm to select the correct or most likely value and continue execution.
> (source: *"[SWEBOK excerpt 7c7c13df07628c3c7d07]."*)

---

### 10. **Replace an Erroneous Value with a Benign Phony Value**
When a value is detected to be in error, substitute a phony (placeholder) value that will have a benign effect on the rest of execution, allowing the program to proceed without propagating the fault.
> (source: *"[SWEBOK excerpt 7c7c13df07628c3c7d07]."*)

---

### 11. **Apply Fault Tolerance as a Reliability-Enhancing Collection of Techniques**
Treat fault tolerance holistically: it increases [SWEBOK excerpt df8942c5d29480ba8301] when full recovery is not possible.
> (source: *"[SWEBOK excerpt 909de8a0fa8186bde761]."*)

---

### 12. **Use Assertions for Runtime Checks**
Place executable assertions (predicates) in the program to perform runtime checks. These are especially valuable in high-reliability programs for catching problems like mismatched interface assumptions before they propagate into failures.
> (source: *"[SWEBOK excerpt 5911453b0a4f5e43261b]. [SWEBOK excerpt 4b5d09b3a87e6f492d8f]."*)

---

### 13. **Design by Contract (Preconditions and Postconditions)**
Include preconditions and postconditions for each routine so that contracts are precisely specified. When violations are detected at runtime, they can be handled cleanly rather than causing undefined behavior throughout the system.
> (source: *"[SWEBOK excerpt 0b7264f99dd70678ccd5]."*)
