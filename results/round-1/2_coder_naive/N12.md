### Guidelines for Measuring Numerical Test Discrepancy

**1. Replace the fixed absolute threshold with relative error — [SWEBOK excerpt 7454b7d6506d5d7642c4] magnitude of the true value.**

Absolute error (|x\* − x|) is scale-dependent and therefore misleading. The correct measure is relative error: |x\* − x| / |x|. This scales with the value being tested, so a tolerance that is appropriate for a result of 0.0001 is also appropriate for a result of 1,000,000.

(source: *"[SWEBOK excerpt dbfe1e860c789f3877c3]."*)

---

**2. Treat relative error as the preferred and more intuitive measure of error size.**

A fixed absolute threshold of 0.001 is not intuitive across different magnitudes. Using relative error aligns the tolerance with the actual scale of the computation, making the acceptance criterion meaningful regardless of whether results are very large or very small.

(source: *"[SWEBOK excerpt 297dadd84958fa3cc461]."*)

---

**3. Understand that absolute error alone is deceptive across different magnitudes (use the SWEBOK's own example as a guide).**

An absolute error of 1 means something very different depending on context: it represents a relative error of 10⁻⁶ when the true value is 1,000,001 (essentially exact), but a relative error of 0.1 (10%) when the true value is 11. A fixed absolute threshold like 0.001 fails to capture this distinction.

(source: *"[SWEBOK excerpt 3baaec5a616a729ec42c]⁻⁶, [SWEBOK excerpt 8f40bc3ffa6de1a9ad8f]."*)

---

**4. Use the relative error to determine how many leading significant digits of the result can be trusted.**

[SWEBOK excerpt 253e990a63222869868b] less than 5 × 10⁻ᵏ⁻¹. This directly tells you how many leading digits of the computed result match those of the true value, providing a principled, scale-independent measure of correctness.

(source: *"[SWEBOK excerpt b94e7b1e7ea33ee80851]⁻ᵏ⁻¹. [SWEBOK excerpt 2741fc0f4da1dd65f224]."*)

---

**5. Distinguish accuracy from precision when evaluating test results.**

The test should be checking *accuracy* — how close the computed value is to the true value — not merely *precision* (consistency among repeated computations). Confusing the two can lead to a test that passes consistently incorrect results.

(source: *"[SWEBOK excerpt b586fdd39148fb34c49b]."*)

---

**6. Note that relative error is undefined when the true value is zero; handle this case separately.**

The relative error formula breaks down when the expected value x = 0, because division by zero is undefined. In such cases, an alternative (such as a small absolute tolerance or a combined absolute/relative threshold) must be used.

(source: *"[SWEBOK excerpt dbfe1e860c789f3877c3]."*)
