### Question

How should test inputs be chosen for a function that accepts numeric values within a valid range?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

Here are the guidelines from SWEBOK for choosing test inputs for a function that accepts numeric values within a valid range:

---

### 1. Partition the Input Domain into Equivalence Classes and Pick a Representative Value from Each

Divide all possible inputs into subsets (equivalence classes) — separating valid inputs from invalid/out-of-range inputs — and select at least one representative test case from each class. This avoids redundancy while ensuring broad coverage.

> (source: "[SWEBOK excerpt e279d64d08518504c456] [SWEBOK excerpt 1a60498744b577380a00].")

---

### 2. Test On or Near the Boundaries of the Valid Range

Choose test cases at or close to the extreme ends of the input range, because faults are especially likely to cluster at those points.

> (source: "[SWEBOK excerpt bedee61fb08d8b967278].")

---

### 3. Also Test Outside the Valid Range (Robustness Testing)

Extend boundary value testing by including inputs *outside* the valid range to verify the function handles unexpected or erroneous inputs gracefully.

> (source: "[SWEBOK excerpt ac52d3263555a546a515].")

---

### 4. Select Tests Aimed at Detecting Specific Categories of Faults (Domain Errors)

Use specification-based (black-box) techniques with the explicit goal of selecting inputs from the domain that expose specific fault categories — confirming the function manages inputs within the required range and returns the correct output.

> (source: "[SWEBOK excerpt 094d0a895b498b2baf0f].")

---

### 5. Use Random Sampling Within the Input Domain

Supplement structured selection with randomly chosen inputs from within the known input domain. Enhanced forms, such as adaptive random testing, can further guide the random sampling with additional criteria.

> (source: "[SWEBOK excerpt 7466320afd0b82fed0f0].")

---

### 6. Apply Combinatorial Techniques When Multiple Parameters Interact

If the function has more than one numeric parameter, systematically derive test cases that cover combinations of their values (e.g., pairwise testing), ensuring interactions between parameters are exercised.

> (source: "[SWEBOK excerpt 12bb367a5311e46b2a98]. … [SWEBOK excerpt 84129f160b87efa4ccba].")

---

**Summary:** SWEBOK's guidance converges on four core ideas for numeric range testing: (1) partition inputs into valid/invalid classes and sample each; (2) concentrate test cases at and near boundaries; (3) go beyond the range to test robustness; and (4) complement these with random and combinatorial selection for broader coverage.
