## Guidelines for Choosing Test Inputs for a Numeric-Range Function

### 1. Partition the input domain into equivalence classes and pick one representative from each

Equivalence partitioning divides the input domain into subsets based on a criterion or relation—such as valid inputs the function accepts and invalid inputs it must reject. A representative test case (sometimes only one) is then drawn from each class, on the rationale that all members of the class are expected to behave the same way.

### 2. Always include values at or near each boundary of the valid range

Boundary value analysis mandates that test cases be [SWEBOK excerpt a1c5d3139ac43e6ab60a]. The rationale is [SWEBOK excerpt 028ee51fe875384b510f] (minimum and maximum) values of inputs.

> (source: "[SWEBOK excerpt bedee61fb08d8b967278]." — `/workspace/swebok-v4/root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md`)

### 3. Also include at least one value clearly inside the valid range

Along with boundary values, a representative value from inside the valid equivalence class should be included to confirm normal, in-range processing works correctly.

> (source: "[SWEBOK excerpt bda2b791e2a71d48fe6c] … [SWEBOK excerpt 83b36aaa6987b9eb0caf]." — `/workspace/swebok-v4/root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md`)

### 4. Include values outside the valid range to test robustness (robustness testing)

An extension of boundary value analysis—called **robustness testing**—calls for test cases chosen **outside** the input domain. This checks whether the function handles unexpected or erroneous inputs gracefully (e.g., with an error message or error-processing routine).

> (source: "[SWEBOK excerpt ac52d3263555a546a515]." — `/workspace/swebok-v4/root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md`)

### 5. Supplement with randomly selected inputs from within the domain

Random testing involves generating test cases at random from the known input domain. It provides a relatively simple approach to automation and can be enhanced with adaptive strategies (e.g., adaptive random testing) that use additional selection criteria to direct sampling across the domain.

> (source: "[SWEBOK excerpt 2e0f1efa93239b85b4bd]." — `/workspace/swebok-v4/root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Random Testing and Evidence-Based Software Engineering Approaches.md`)

### 6. Apply error guessing to anticipate plausible fault-inducing values

Based on the tester's experience and [SWEBOK excerpt df027194885f5813d595], error guessing means designing test cases specifically targeted at the most plausible faults—such as off-by-one errors, zero, or values just inside/outside a constraint.

### 7. Combine specification-based and structure-based techniques for greater coverage

Combining them, subject to organizational constraints, improves the overall effectiveness of the test suite.
