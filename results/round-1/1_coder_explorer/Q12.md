### Question

How should modules be organized so that the software stays easy to maintain, and how can an existing badly structured program be improved without its users noticing any difference?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
Modules should be organized by assigning each a single responsibility, maximizing internal cohesion, minimizing coupling with other modules, hiding implementation details behind well-defined interfaces, and separating concerns so that each part of the system can be reasoned about in isolation. When an existing program is poorly structured, **refactoring** is the prescribed technique: it reorganizes the program's internal structure and improves maintainability without changing the program's externally observable behavior. In Agile/CI environments, refactoring should be done continuously to keep growing complexity under control.
