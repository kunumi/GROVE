### Question

Our orders table repeats the customer's name and address on every order row, and after a customer moves some rows show the old address while others show the new one. How should the tables be restructured, and what does that cost when querying the data?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
Your orders table has a classic normalization problem: storing customer name and address on every order row creates data redundancy that causes update anomalies — when a customer moves, only some rows get updated. The fix is to split the data into a separate `Customers` table and reference it from `Orders` via a foreign key. The direct cost of this restructuring is query-time overhead: normalized schemas require table joins, which increase processing time.
