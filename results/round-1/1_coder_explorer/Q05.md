### Question

How should test inputs be chosen for a function that accepts numeric values within a valid range?

Answer with a list of guidelines. After each guideline, cite the source it comes from: the path of the SWEBOK file if you have it, otherwise a verbatim quote of at least 8 words from the passage, in the form (source: ...).

### Answer

# Summary
SWEBOK v4 provides multiple complementary techniques for choosing test inputs for a function that accepts numeric values within a valid range. The core approach combines **equivalence partitioning** (select representatives from valid and invalid classes), **boundary value analysis** (test on and near range limits, where faults concentrate), and **robustness testing** (test outside the range too). These are supplemented by combinatorial techniques for multi-parameter functions, exception-forcing tests, random selection, and experience-based error guessing.

# Guidelines

- **Partition inputs into equivalence classes** (valid range and out-of-range) and select at least one representative test case from each class. Invalid inputs should trigger error messages or error processing. (source: `root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md` — *"[SWEBOK excerpt bda2b791e2a71d48fe6c] … [SWEBOK excerpt 83b36aaa6987b9eb0caf]."*)

- **Choose test cases on or near the boundaries of the valid range**, because many faults concentrate near the extreme values of inputs. (source: `root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md` — *"[SWEBOK excerpt bedee61fb08d8b967278]."*)

- **Also choose test cases outside the valid range** (robustness testing) to verify the function's behavior when it receives unexpected or erroneous numeric inputs. (source: `root/Software Testing Methodologies and Techniques/Boundary Value Analysis and Syntax Testing Techniques.md` — *"[SWEBOK excerpt 32408e7aeb57f6cc8404]."*)

- **Use combinatorial techniques** (all-combinations, pair-wise, each-choice, base-choice) to systematically cover combinations of values when the function has multiple numeric parameters. (source: `root/Software Testing Methodologies and Techniques/Combinatorial Test Techniques Overview.md` — *"[SWEBOK excerpt 12bb367a5311e46b2a98]."*)

- **Force numeric exceptions** (overflow, underflow, data exceptions) with dedicated negative test cases to verify that error handling is correct. (source: `root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Exception Testing and Error Handling in Software Testing.md` — *"[SWEBOK excerpt 963f70a5243f19882d26]."*)

- **Supplement with random test case selection**, drawing values from an input distribution, especially for reliability-oriented testing. (source: `root/Testing Methodologies and Quality Assurance Practices/Software Testing Techniques, Measurement, and Management/Testing Approaches and Test Case Selection Methods/Deterministic vs. Random Test Case Selection.md` — *"[SWEBOK excerpt 097224383f2f8ec6ba2c]."*)

- **Apply error guessing** — use the history of faults found in similar functions and the engineer's expertise to design additional test cases targeting the most plausible errors. (source: `root/Testing Methodologies and Quality Assurance Practices/Testing Approaches and Execution Strategies/Software Testing Techniques and Methodologies/Experience-Based Techniques for Test Suite Generation.md` — *"[SWEBOK excerpt a88edf90b37a2d7aaba8]."*)
