### Question

How should I derive test cases for a component whose behavior depends on its current state and on the events it receives?

### Answer

# Summary

For state-dependent components, derive positive test cases from each defined state transition and negative test cases from state/event combinations not present in the model. Use state transition diagrams, BDD scenarios, and formal models to systematically generate test cases covering behavioral aspects.

# Guidelines

- Derive positive test cases for each defined transition in a state model, and derive negative test cases [SWEBOK excerpt d872898bacd2837dcf5e] in the model. (source: /workspace/swebok-v4/root/Requirements Management, Quality, and Testing Practices/Deriving Test Cases from Requirements Models.md)

- Use state (transition) diagrams and statecharts [SWEBOK excerpt 902da0d428edb085ff0f]. (source: /workspace/swebok-v4/root/Software Design Concerns, Documentation, and Modeling/Modeling, Patterns, and Domain-Specific Design Approaches/Interaction and Behavioral Diagrams in Software Design.md)

- Apply state transition testing techniques, which focus on representing the system under test with a finite-state machine, to derive test cases. (source: /workspace/swebok-v4/root/Software Testing Methodologies and Techniques/Cause-Effect Graphing and State Transition Testing.md)

- Derive test suite to cover [SWEBOK excerpt 411b5f76869eac0dd066] using scenario-based testing [SWEBOK excerpt d46dbff794ce3a10f11a] behavioral aspects. (source: /workspace/swebok-v4/root/Software Testing Methodologies and Techniques/Scenario-Based Testing for Requirements Validation.md)

- Use BDD scenarios in the form "Given [context], when [stimulus], then [outcome]" to specify and derive acceptance test cases covering different behavioral scenarios, including both valid and invalid states.
