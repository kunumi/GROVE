What general practices should developers follow when writing code so that attackers cannot exploit it?

# Summary

Developers should follow secure coding practices spanning input validation, privilege management, error handling, dependency management, and quality assurance to prevent attackers from exploiting software vulnerabilities.

# Guidelines

- Validate all input to prevent malicious data from entering the system. (source: /workspace/swebok-v4/root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Top 10 Software Security Practices.md)
- Heed compiler warnings and keep designs simple, applying default deny principles. (source: /workspace/swebok-v4/root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices and Design Principles.md)
- Adhere to the principle of least privilege and sanitize data sent to other software. (source: /workspace/swebok-v4/root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Security Best Practices for Software Development.md)
- Practice defense in depth and use effective quality assurance techniques. (source: /workspace/swebok-v4/root/Software Security Engineering and Professional Practice/Security Development and Testing Practices/Software Security Best Practices.md)
- Structure code so that sections requiring extra privileges are isolated modules, as small as possible. (source: /workspace/swebok-v4/root/Software Security Engineering and Professional Practice/Secure Software Development Standards and Practices/Secure Software Design and Implementation Practices/Software Construction Security and Privilege Management.md)
- Validate all program assumptions; if not possible, document them so maintainers know what attackers may try to invalidate. - Check every function's error status and restore prior state before terminating on security-relevant errors.
